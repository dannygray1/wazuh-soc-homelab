# SOC Investigation Report: Windows Failed-Logon Detection

**Project:** Wazuh SOC Home Lab  
**Investigation Date:** October 20–21, 2026  
**Endpoint:** SOC-WIN11-01  
**SIEM:** Wazuh 4.14.9  
**Windows Event ID:** 4625  
**Wazuh Rule ID:** 60122  
**Alert Severity:** Level 5  
**Status:** Closed — Authorized Lab Simulation

## 1. Investigation Objective

Generate a controlled failed-authentication event on a Windows 11 endpoint, verify its detection by Wazuh, analyze the associated security telemetry, and document the findings using a SOC analyst investigation workflow.

The activity was performed within an isolated virtual lab using a temporary local test account.

## 3. Detection Summary

A controlled authentication attempt was performed using an intentionally incorrect password.

Windows recorded a failed-logon event, and Wazuh generated an alert identifying the authentication failure.

The detection was classified by Wazuh as:

| Field | Value |
|---|---|
| Rule ID | 60122 |
| Rule Description | Logon Failure - Unknown user or bad password |
| Severity | Level 5 |
| Event Source | Windows Security Log |
| Windows Event ID | 4625 |
| Authentication Package | NTLM |
| Logon Type | 3 — Network |
| Source Address | 127.0.0.1 |

The loopback source address indicates that the authentication attempt originated locally on the monitored Windows endpoint.

## 4. Event Generation

A temporary Windows local account named `SOC-Lab-TestAccount` was created for authentication testing.

Windows logon auditing was verified to include failed-logon events.

A controlled failed-authentication attempt was generated using PowerShell:

```powershell
net use \\127.0.0.1\IPC$ /user:.\SOC-Lab-TestAccount *
```

An intentionally incorrect password was supplied.

Windows returned:

```text
System error 1326 has occurred.
The user name or password is incorrect.
```

This confirmed that the authentication request was rejected.

## 5. Windows Event Log Investigation

Windows Security Event ID `4625` was identified using PowerShell.

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    Id = 4625
    StartTime = (Get-Date).AddMinutes(-15)
} -ErrorAction SilentlyContinue |
Where-Object { $_.Message -like '*SOC-Lab-TestAccount*' } |
Select-Object TimeCreated, Id, Message |
Format-List
```

The event details included:

| Field | Value |
|---|---|
| Event ID | 4625 |
| Account Name | SOC-Lab-TestAccount |
| Logon Type | 3 |
| Source Network Address | 127.0.0.1 |
| Authentication Package | NTLM |
| Status | 0xC000006D |
| Substatus | 0xC000006A |

The status and substatus values indicated an authentication failure caused by an incorrect password.

## 6. Wazuh Alert Investigation

The event was located in **Wazuh → Threat Hunting → Events** using the following search:

```text
data.win.system.eventID:4625
```

The corresponding alert was generated by Wazuh Rule `60122`.

The alert's document details confirmed the endpoint name, authentication failure, test account, source address, logon type, and severity.

Wazuh also associated the rule with MITRE ATT&CK technique `T1531` (Account Access Removal).

This mapping was treated as rule metadata rather than proof that account access removal had occurred. The actual event evidence supported an incorrect-password authentication failure.

## 7. Timestamp Discrepancy and Validation

During the initial test on October 20, a discrepancy was observed between the Windows event timestamp and the Wazuh dashboard timestamp.

| Source | Initial Timestamp |
|---|---|
| Windows Security Log | October 20, 2026, 5:14:03 PM |
| Wazuh Dashboard | October 20, 2026, 8:14:05 PM |

The Windows VM's time-zone configuration was identified as incorrect and subsequently corrected to Eastern Time.

A second controlled authentication failure was generated on October 21 to validate the correction.

| Source | Validation Timestamp |
|---|---|
| Windows Security Log | October 21, 2026, 7:00:04 PM EDT |
| Wazuh Dashboard | October 21, 2026, 7:00:05 PM |
| Windows Event Record ID | 42095 |

## 8. Investigation Findings

The investigation established the following:

- A controlled authentication attempt using an incorrect password generated Windows Security Event ID `4625`.
- The Windows endpoint successfully forwarded the security event to Wazuh.
- Wazuh Rule `60122` identified the authentication failure and generated a Level 5 alert.
- The event originated from the local loopback address (`127.0.0.1`) using network logon type `3`.
- Authentication status codes `0xC000006D` and `0xC000006A` were consistent with an incorrect-password attempt.
- An initial timestamp discrepancy was traced to the Windows VM's time-zone configuration.
- A second test confirmed that the Windows Event Log and Wazuh dashboard displayed consistent timestamps after the correction.

## 9. Investigation Disposition

**Classification:** Authorized Security Testing  
**Disposition:** Benign — Expected Lab Activity  
**Status:** Closed

The authentication failure was intentionally generated as part of a controlled SOC detection exercise.

The available evidence was consistent with the authorized test activity. No indicators of unauthorized access were identified in the investigated event.

No containment or remediation actions were required for the simulated authentication failure.

## 10. Lessons Learned

- Windows Security Event ID `4625` provides valuable authentication-failure telemetry.
- Authentication status codes, logon types, and source addresses help establish the context of security events.
- Correlating Windows Event Logs with SIEM alerts helps validate endpoint monitoring and detection capabilities.
- Time-zone configuration and timestamp consistency are important considerations during security investigations.
- MITRE ATT&CK mappings should be evaluated against actual event evidence rather than treated as confirmation of attacker behavior.
- Documenting investigation findings and disposition is an essential part of the SOC analyst workflow.
