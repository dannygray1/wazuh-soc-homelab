# Wazuh SIEM Installation and Validation

**Environment:** Oracle VirtualBox  
**Virtual Machine:** SOC-WAZUH-01  
**Operating System:** Ubuntu Server 24.04.5 LTS  
**Wazuh Version:** 4.14.9  
**Deployment:** Single-node, all-in-one installation  
**Status:** Completed

## Objective

Deploy a functional Wazuh Security Information and Event Management (SIEM) environment to collect, analyze, and investigate security events generated by a Windows 11 endpoint.

The Wazuh server was deployed on an Ubuntu Server virtual machine within an isolated SOC home lab.

## Server Configuration

| Component | Configuration |
|---|---|
| Virtualization Platform | Oracle VirtualBox |
| Hostname | soc-wazuh-01 |
| Operating System | Ubuntu Server 24.04.5 LTS |
| Memory | 8 GB RAM |
| Processors | 4 virtual CPUs |
| Virtual Disk | 60 GB |
| NAT IP Address | 10.0.2.15 |
| Internal Network IP | 192.168.56.10 |
| Internal Network | SOC-LAB |

## Installation Method

Wazuh was installed using the official installation assistant with the all-in-one deployment option.

The installation script was downloaded using:

```bash
curl -sO https://packages.wazuh.com/4.14/wazuh-install.sh
```

The installation was started with:

```bash
sudo bash wazuh-install.sh -a
```

The all-in-one installation deployed the Wazuh server components on a single Ubuntu virtual machine.

## Wazuh Components

The following services were installed and verified:

| Service | Purpose |
|---|---|
| wazuh-manager | Receives and analyzes security events from agents |
| wazuh-indexer | Stores and indexes security event data |
| wazuh-dashboard | Provides the web interface for monitoring and investigation |
| filebeat | Forwards Wazuh alert data to the indexer |

## Service Validation

Service status was checked using:

```bash
sudo systemctl status wazuh-manager
sudo systemctl status wazuh-indexer
sudo systemctl status wazuh-dashboard
sudo systemctl status filebeat
```

All four services were confirmed to be active and running.

## Dashboard Access

The Wazuh dashboard was configured to use HTTPS on port 443.

Rather than exposing the dashboard directly to the physical network, an SSH local port-forwarding tunnel was used to access the dashboard from the Windows host.

The following command was executed in PowerShell on the physical Windows computer:

```powershell
ssh -i "$env:USERPROFILE\.ssh\wazuh_soc_lab_ed25519" -p 2222 -N -L 8443:127.0.0.1:443 danny@127.0.0.1
```

With the SSH tunnel active, the dashboard was accessed at:

```text
https://127.0.0.1:8443
```

The dashboard used a self-signed TLS certificate, which caused an expected browser certificate warning.

The dashboard login was completed successfully.

## Virtual Machine Snapshot

After confirming successful installation, a VirtualBox snapshot was created:

`Wazuh-4.14.9-Installed`

This snapshot established a recovery point before deploying agents and beginning security monitoring exercises.

## Lessons Learned

- An all-in-one Wazuh deployment is suitable for a small educational SOC lab.
- A SIEM relies on multiple services working together to ingest, store, and display security telemetry.
- Validating individual services helps distinguish installation problems from connectivity or dashboard issues.
- SSH local port forwarding provides a convenient method for accessing internal web services without directly publishing them on the physical network.
- Self-signed certificates provide encryption but do not establish trust through a public certificate authority.
- Virtual machine snapshots provide recovery points before significant configuration changes.
